# Repository guidance

Use the [MIT Coding and Comment Style guide](https://mitcommlab.mit.edu/broad/commkit/coding-and-comment-style/)
and the repository's existing conventions.

## Writing

Applies to documentation, comments, commits, PRs and dashboard text.

- Lead with what something does and why.
- Write short, active, specific sentences. Cut any sentence the reader can't
  act on or verify, such as "Solar stays connected."
- Use lists and tables over paragraphs. Give units and defaults.
- No filler, hedging, hyperbole or narration about the work.
- Cut before adding; a change to documentation should usually shrink it.

## Code

- Prefer clear names over comments. Comment only on rationale, units,
  constraints and API quirks.
- Follow existing formatting and line-length settings.

## Documentation

- A README is a short summary that links to deeper docs.
- Check claims against the code, and update docs in the same change as
  behavior.
- Keep generated API documentation in sync with its source models.

## Dashboard

Use labels, units and tooltips, not sentences explaining metrics or what the
system is doing.
